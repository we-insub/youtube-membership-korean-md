# 검색 제목과 메타태그 작성 지침

네이버·구글에 노출할 페이지의 본문을 읽고, 검색 결과와 링크 공유 미리보기에 쓸 제목과 설명을 작성한다. 독자가 찾는 정보가 실제 페이지 어디에 있는지 먼저 확인한다.

## 네이버·구글 검색 제목과 설명 쓰기

이 문서에서 SEO는 일반 웹 검색 최적화, NEO는 네이버 웹 검색 최적화를 가리킨다. 두 검색엔진에 공통으로 쓸 제목과 설명을 한 벌 작성한다. HTML의 `<title>`은 페이지 제목 요소다. 검색엔진은 이 제목과 화면의 대표 제목, 페이지를 가리키는 링크 문구 등을 바탕으로 검색 결과에 표시할 제목을 정한다. 제목을 바꾸어도 특정 순위나 문구로 표시된다는 보장은 없다. [네이버 검색 결과의 제목과 설명](https://searchadvisor.naver.com/guide/faq-serpedit) · [구글 제목 링크](https://developers.google.com/search/docs/appearance/title-link?hl=ko)

1. **독자가 쓰는 말로 주제를 정한다.** 검색창에 ‘공방 예약 취소 언제까지’라고 입력할 수 있다. 화면 제목은 ‘도예 수업은 언제까지 취소할 수 있나요?’ 또는 ‘도예 수업 예약 취소 안내’처럼 쓴다. 검색어의 조사 생략이나 띄어쓰기 오류까지 흉내 낼 필요는 없다.
2. **페이지마다 고유한 `<title>`을 하나 쓴다.** 홈페이지는 브랜드와 사이트의 성격이 드러나게, 상세 페이지는 방문자가 찾는 주제가 앞에 오게 쓴다. 화면의 대표 제목(`<h1>`)과 단어가 조금 달라도 무엇을 다루는지는 일치해야 한다. 키워드 반복 횟수를 목표로 삼지 않는다. [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content) · [구글 제목 링크](https://developers.google.com/search/docs/appearance/title-link?hl=ko)
3. **`meta description`에는 답이나 조건을 한두 문장으로 쓴다.** 제목이 ‘도예 수업 예약 취소 안내’라면 설명에는 실제 취소 기한과 방법을 넣는다. 네이버는 검색어와 본문 등을 살펴 설명을 고른다. 구글은 검색 결과의 설명문(스니펫)을 주로 본문에서 만들고, 메타 설명이 더 적합하면 그 문구를 사용한다. 구글은 메타 설명 자체를 검색 순위 계산에 쓰지 않는다고 밝혔다. [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content) · [구글 스니펫](https://developers.google.com/search/docs/appearance/snippet?hl=ko) · [구글의 메타태그와 검색 순위 설명](https://developers.google.com/search/blog/2009/09/google-does-not-use-keywords-meta-tag?hl=ko)
4. **공유 미리보기의 `og:title`과 `og:description`도 같은 사실을 담는다.** 링크를 받은 사람이 어느 브랜드의 어떤 페이지인지 알 수 있게 쓴다. 네이버 웹 검색은 두 값 모두를 제목·설명의 후보로 참고할 수 있고, 구글도 제목을 정할 때 `og:title`을 참고할 수 있다. [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content) · [구글 제목 링크](https://developers.google.com/search/docs/appearance/title-link?hl=ko)

공유 카드까지 구성할 때 Open Graph의 기본 필드는 `og:title`, `og:type`, `og:image`, `og:url`이다. `og:description`은 설명을 보태는 선택 항목이다. 일반 안내 페이지라면 유형에 `website`를 쓸 수 있다. `og:url`에는 해당 콘텐츠의 고정된 대표 주소를 넣고, `og:image`에는 로그인 없이 이미지 자체가 열리는 전체 주소를 넣는다. 관리자 화면이나 곧 만료될 임시 링크는 쓰지 않는다. 실제 이미지를 확인했다면 `og:image:alt`에 이미지 내용을 짧게 적는다. [Open Graph 기본·이미지 속성](https://ogp.me/) · [네이버 오픈 그래프 이미지 안내](https://searchadvisor.naver.com/guide/markup-content)

**글자 수를 점검할 때** — 네이버 ‘사이트 간단 체크’는 메인 페이지의 제목 40자 이내, 설명 80자 이내를 권장한다. 네이버의 개별 페이지 제목 가이드는 별도의 글자 수 제한을 두지 않는다. 구글도 기기 화면 폭 등에 맞춰 제목과 설명을 줄여 표시한다. 중요한 정보부터 쓰고, 두 엔진에 같은 글자 수를 적용하려고 기한이나 예외를 빼지 않는다. [네이버 사이트 간단 체크](https://searchadvisor.naver.com/guide/diagnose-site) · [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content) · [구글 제목 링크](https://developers.google.com/search/docs/appearance/title-link?hl=ko) · [구글 스니펫](https://developers.google.com/search/docs/appearance/snippet?hl=ko)

**키워드가 나열된 설명을 고치는 예** — “성수 공방 성수 도예 성수 도자기 원데이클래스”는 장소와 유사어를 반복해 수업 내용이나 이 페이지에서 알 수 있는 것이 드러나지 않는다. 성수에서 물레로 컵을 만드는 하루 수업이며 페이지에 일정과 수강료가 있다면 “성수에서 물레로 컵을 만드는 하루 수업입니다. 수업 일정과 수강료를 확인하세요.”라고 쓸 수 있다.

검색어를 정했다면 제목과 본문에 자연스럽게 쓴다. 구글 웹 검색은 `<meta name="keywords">`를 색인 생성과 순위 산정에 사용하지 않으므로 구글 노출을 위해 이 태그를 추가할 필요가 없다. [구글에서 지원하는 메타태그](https://developers.google.com/search/docs/crawling-indexing/special-tags?hl=ko)

## AI 인용을 고려할 때 확인할 본문

AEO(답변형 검색 최적화)와 GEO(생성형 검색 최적화)를 고려할 때도 먼저 독자의 질문에 답한다. 네이버의 공식형·멀티출처형 AI 브리핑은 질문과 관련 있는 웹문서를 골라 답변과 출처를 제공한다. 구글 AI 개요·AI 모드에 참조 링크로 표시될 자격을 갖추려면 페이지가 구글에 색인되어 있고 검색 결과에 스니펫과 함께 표시될 수 있어야 한다. 어떤 페이지를 근거로 삼고 링크를 보여 줄지는 서비스가 결정한다. [네이버 공식형·멀티출처형 AI 브리핑](https://help.naver.com/service/5626/contents/24120?lang=ko&osType=COMMONOS) · [구글 검색의 AI 기능](https://developers.google.com/search/docs/appearance/ai-features?hl=ko)

아래 문단 구성은 독자가 답과 근거를 쉽게 찾게 하는 편집 방법이다. 구글은 직접 경험한 내용이나 독자적인 자료처럼 독자에게 가치 있는 정보에 집중하도록 권한다. 구글 생성형 검색에 노출되려고 본문을 일정한 길이로 쪼개거나 별도 AI 마크업·`llms.txt`를 만들 필요는 없다. [구글 생성형 AI 검색 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide?hl=ko)

- 기한을 묻는 질문이면 기한부터, 방법을 묻는 질문이면 첫 행동부터 쓴다. 문단만 따로 읽어도 **어떤 상품·서비스에 적용되는지** 알 수 있게 한다.
- 답의 뜻을 바꾸는 조건은 답 가까이에 둔다. 예를 들어 ‘전날까지 무료’라고 줄이면 오후 6시 마감이 자정으로 오해될 수 있다. 자료에 있는 시각과 예외를 보존한다.
- 요금·통계·비교·정책은 운영자의 안내, 원자료, 직접 측정한 결과 등 확인할 수 있는 근거를 사용한다. 시점에 따라 달라지는 수치에는 자료에서 확인한 기준일을 붙인다. 다른 기관의 자료를 인용할 때는 해당 문장 가까이에 원문 링크를 둔다.
- 실제로 자주 받는 질문은 문답으로, 짧은 이용 절차는 순서대로 쓴다. 한 문단이면 충분한 페이지에 같은 내용의 FAQ를 덧붙이지 않는다. 구글은 2026년 5월 7일부터 FAQ 리치 결과 표시를 중단했다. 방문자를 위한 문답은 그대로 활용하되, `FAQPage`를 추가해 구글 FAQ 리치 결과나 AI 인용을 얻는다고 안내하지 않는다. [구글 검색 문서 변경 기록](https://developers.google.com/search/updates?hl=ko) · [구글 생성형 AI 검색 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide?hl=ko)
- 구조화된 데이터(예: JSON-LD)를 쓰면 가격·평점 등 표시하는 값이 방문자가 볼 수 있는 본문과 일치해야 한다. 구글이 지원하는 유형과 요건에 맞으면 추가 정보가 붙는 검색 결과의 후보가 된다. 실제 표시 여부는 구글이 정한다. [구글 구조화된 데이터 가이드라인](https://developers.google.com/search/docs/appearance/structured-data/sd-policies?hl=ko)
- **게시 후 확인한다.** Search Console의 ‘생성형 AI 실적 보고서(Google 검색)’에서는 AI 개요와 AI 모드에서 내 사이트로 연결되는 링크가 표시된 노출수를 볼 수 있다. 노출이 적으면 보고서 자체가 보이지 않을 수 있다. 보고서가 없으면 노출을 0회라고 단정하지 말고 ‘설정 → Google 검색 생성형 AI’에서 사이트의 포함·제외 및 상위 속성에서 상속한 설정도 확인한다. 이 수치만으로 링크 클릭수, 특정 답변이 문장을 직접 인용한 횟수, 다른 서비스의 인용 횟수는 알 수 없다. [구글 생성형 AI 실적](https://support.google.com/webmasters/answer/16984139?hl=ko) · [구글 검색 생성형 AI 제어](https://support.google.com/webmasters/answer/16908024?hl=ko)

## 기존 `<head>`를 고칠 때 함께 확인할 설정

- **검색에 남길 페이지인지 확인한다.** `robots.txt`는 로봇이 읽을 수 있는 경로를 정한다. `noindex`는 검색 결과에서 페이지를 제외할 때 쓰며, 로봇이 해당 페이지에 접근해야 읽을 수 있다. 구글에서는 `robots.txt`만으로 수집을 막아도 다른 곳에서 발견한 URL이 검색에 남을 수 있다. 제목·설명을 고치는 작업에서 기존 색인 설정까지 함께 바꾸지 않는다. [구글의 색인 제외 방법](https://developers.google.com/search/docs/crawling-indexing/block-indexing?hl=ko) · [네이버 로봇 메타태그](https://searchadvisor.naver.com/guide/markup-structure)
- **설명문이 비어 보이면 미리보기 제한도 확인한다.** 구글의 `nosnippet`이나 `max-snippet:0`은 페이지의 텍스트 스니펫을 막는다. `div`, `section`, `span`에 지정한 `data-nosnippet`은 해당 부분의 텍스트를 스니펫에서 제외한다. HTML의 `robots`·`googlebot`과 서버 응답의 `X-Robots-Tag`를 함께 본다. 구글에 적용되는 규칙끼리 충돌하면 더 제한적인 쪽이 적용된다. 네이버의 `nosourceinfo`는 네이버가 AI로 생성하는 사이트 출처 설명을 제어한다. 이를 모든 AI 인용을 차단하는 설정으로 해석하지 않는다. [구글 스니펫·로봇 규칙](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag?hl=ko) · [네이버 로봇 메타태그](https://searchadvisor.naver.com/guide/markup-structure)
- **같은 내용에 주소가 여러 개인지 확인한다.** `<link rel="canonical">`은 검색엔진에 선호하는 대표 URL을 알려 주는 링크 요소다. 중복 페이지에 적용할 때는 해당 콘텐츠의 대표 주소를 전체 URL로 넣는다. 예를 들어 수업 상세 페이지를 모두 홈페이지로 지정하면 각각 다른 수업을 중복으로 묶으라는 잘못된 신호가 된다. HTML의 대표 URL과 사이트맵에서 서로 다른 주소를 권장하지 않는지도 본다. `og:url`은 소셜 그래프에서 그 콘텐츠를 식별하는 주소이므로 검색용 대표 URL은 `rel="canonical"`에서 별도로 확인한다. [네이버 선호 URL](https://searchadvisor.naver.com/guide/markup-structure) · [구글 표준 URL 지정](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls?hl=ko)
- **소유 확인 태그를 보존한다.** `google-site-verification`과 `naver-site-verification`은 각 도구에서 사이트 관리 권한을 확인하는 값이다. HTML 태그 방식으로 인증할 때만 해당 도구가 발급한 값을 홈페이지의 `<head>`에 넣는다. 문구를 교체할 때 기존 인증값을 덮어쓰지 않는다. [구글 소유권 확인](https://support.google.com/webmasters/answer/9008080?hl=ko) · [네이버 사이트 소유확인](https://searchadvisor.naver.com/guide/faq-start-register)

## 작성 예시 — 도예 수업 예약 취소 안내

**입력할 페이지 본문(가상 브랜드 ‘다온공방’)**

> **도예 수업 예약 취소 안내**  
> 도예 수업은 수업 전날 오후 6시까지 예약 내역에서 무료로 취소할 수 있어요. 그 시간이 지나면 공방에 전화로 문의해 주세요.

**기존 HTML의 `<head>`에서 문구를 교체할 예시** — 사이트 편집기나 플러그인이 이미 이 태그를 출력한다면 해당 입력란을 수정한다. 아래는 문구 네 항목의 교체본이다. 공유 카드까지 새로 구성하려면 대표 URL과 이미지 주소를 확인한 뒤 위의 Open Graph 기본 필드를 갖춘다.

```html
<title>도예 수업 예약 취소 기한과 방법 | 다온공방</title>
<meta name="description" content="다온공방 도예 수업은 수업 전날 오후 6시까지 예약 내역에서 무료로 취소할 수 있어요. 이후에는 공방에 전화로 문의해 주세요.">
<meta property="og:title" content="다온공방 도예 수업 예약 취소 안내">
<meta property="og:description" content="수업 전날 오후 6시까지 예약 내역에서 무료로 취소할 수 있어요. 이후에는 공방에 전화로 문의해 주세요.">
```

**예시 검수** — 검색 제목에서 어떤 수업의 기한과 방법을 다루는지 알 수 있다. 검색 설명과 공유 설명 모두 본문에 있는 ‘수업 전날 오후 6시까지’와 이후 문의 방법을 담았다. 기한이 지난 뒤의 환불 금액은 자료에 없어 설명에서 생략했다.

**공유 카드까지 완성하는 경우** — 같은 사례에서 페이지 유형, 대표 주소, 대표 사진까지 확인했다면 위 네 항목에 아래 항목을 더한다. 여기의 `example.com`은 예시 도메인이다. 게시할 때는 운영 중인 페이지 주소와 직접 열어 본 이미지 주소·사진 설명으로 바꾼다. CMS에 이 값이 이미 있으면 기존 입력란에서 수정한다.

```html
<meta property="og:type" content="website">
<meta property="og:url" content="https://example.com/classes/pottery/cancellation">
<meta property="og:image" content="https://example.com/images/pottery-cups.jpg">
<meta property="og:image:alt" content="다온공방 도예 수업에서 만든 도자기 컵 두 개">
```

## 배포 예시 — 관리자 화면의 문구가 게시 페이지에서 잘릴 때

가상의 ‘밤 & 흙’ 공방에서 수업명을 `"달" 컵 만들기`로 입력했다. CMS가 공통 설명을 출력하는데 편집자가 직접 만든 태그까지 추가하면, 게시된 HTML에 두 문제가 함께 생길 수 있다.

```html
<!-- 오류 예시 -->
<meta name="description" content="공방 홈페이지입니다.">
<meta name="description" content="밤 & 흙 공방에서 "달" 컵을 만드는 수업입니다.">
```

설명이 두 개이고, 두 번째 태그는 ‘달’ 앞의 큰따옴표에서 `content` 값이 끝난다. CMS를 쓴다면 페이지의 검색 설명 입력란에 원문을 넣고 중복으로 추가한 태그를 지운다. 직접 HTML을 만들 때는 템플릿의 HTML 이스케이프 기능을 써서 원문을 한 번만 변환한다. 게시된 HTML과 브라우저가 읽은 값은 다음처럼 대응해야 한다. [HTML 표준의 속성값 문법](https://html.spec.whatwg.org/multipage/syntax.html#attributes-2) · [구글의 유효한 페이지 메타데이터](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata?hl=ko)

```html
<meta name="description" content="밤 &amp; 흙 공방에서 &quot;달&quot; 컵을 만드는 수업입니다.">
```

게시 URL을 열고 개발자 도구 콘솔에서 아래 한 줄을 실행한다. 이 예시에서는 결과가 한 개이고 그 값이 `밤 & 흙 공방에서 "달" 컵을 만드는 수업입니다.`여야 한다. 값에 `&quot;`가 보이면 CMS 입력 전에 이미 변환한 문구를 넣었는지 살핀다.

```javascript
Array.from(document.head.querySelectorAll('meta[name="description" i]'), tag => tag.content)
```

이 검사는 현재 브라우저의 DOM을 읽는다. 자바스크립트나 플러그인이 태그를 바꾼다면 페이지 원본의 `<head>`와도 비교하고, 구글에서 읽을 수 있는 버전은 Search Console의 URL 검사에서 ‘실제 URL 테스트’ 후 렌더링된 HTML을 확인한다. 공유 이미지 주소는 로그아웃한 새 창에서 직접 열어 실제 그림이 나오는지도 확인한다. [구글 렌더링된 소스 확인](https://support.google.com/webmasters/answer/11626894?hl=ko)

**원본에는 설명이 있는데 `document.head`에서 찾을 수 없다면** 태그 바로 앞도 살핀다. 테마가 `<head>` 안에 로고용 `<img>`나 지도용 `<iframe>`을 먼저 출력하는 경우가 한 예다. 구글은 이런 요소를 만나면 머리말이 끝났다고 보고 뒤의 메타데이터를 읽지 않는다. 화면에 보여 줄 로고나 지도는 본문(`<body>`)에 두고, 게시한 페이지에서 제목과 설명이 `<head>` 안에 남아 있는지 다시 확인한다. [구글의 유효한 페이지 메타데이터 안내](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata?hl=ko)

태그가 정상이라면 게시일과 수정한 URL을 기록한다. 이후 검색에 보이지 않거나 클릭이 줄었을 때는 색인 상태, 검색어, 비교 기간 순서로 원인을 좁힌다. [초보자 웹 운영 지침의 URL 검사와 실적 읽기](처음-시작하는-구글-네이버-웹운영.md)

## 복사해서 쓰는 요청문

### 새 페이지의 메타태그를 작성할 때

```text
첨부한 검색 제목·메타태그 지침을 적용해 아래 페이지의 <head>에 넣을 HTML을 작성해 줘.

브랜드·페이지 목적:
화면의 대표 제목과 본문:
독자가 찾는 정보 또는 참고할 검색어(있으면):
확인된 대표 URL·공개 이미지 주소·페이지 유형(있으면):
입력 방식(직접 HTML, CMS의 검색·공유 입력란 등):

본문에서 확인한 사실로 <title>, meta description, og:title, og:description을 작성해 줘.
직접 HTML에 넣는다면 필요한 태그를 코드 블록 하나에 담고 속성값을 올바르게 이스케이프해 줘.
CMS 입력란을 쓴다면 입력할 일반 문구를 필드별로 줘. CMS가 생성하는 태그와 중복되지 않게 해 줘.
공유 카드까지 만들 때는 확인된 유형·대표 URL·이미지로 og:type, og:url, og:image를 채워 줘.
누락된 주소는 지어내지 말고 어느 항목을 확인해야 하는지 알려 줘.
검색 설명 또는 공유 설명만 읽어도 대상과 중요한 조건이 분명한지 확인해 줘.
독자의 질문에 답하는 데 본문의 근거나 조건이 빠져 있다면 확인할 사항을 코드 밖에 따로 적어 줘.
```

### 기존 메타태그를 검수할 때

```text
첨부한 검색 제목·메타태그 지침으로 아래 페이지를 검수해 줘.

브랜드·페이지 목적:
화면의 대표 제목과 본문:
현재 <head>의 제목·메타태그와 CMS 입력 방식:
로봇 설정 관련 HTTP 응답 헤더(확인할 수 있으면):
비교할 다른 페이지의 제목·설명(있으면):

각 제목과 설명이 페이지 주제와 본문 조건을 담는지, 키워드가 반복되는지 확인해 줘.
페이지 안에서 중복 출력된 title·description, 따옴표에서 잘린 속성값을 찾아 줘.
비교할 다른 페이지가 있으면 페이지 간 중복도 확인해 줘. 공개 URL·이미지 여부는 자료로 확인할 수 있는 만큼만 판단해 줘.
기존 대표 URL·로봇 지시어·소유 확인 값은 보존하고, 충돌이 보이면 근거와 확인할 곳만 알려 줘.
고칠 부분은 해당 태그와 이유를 짧게 설명해 줘. 직접 HTML을 쓰면 교체할 태그만 코드 블록 하나로,
CMS가 자동 생성하면 바꿀 입력란과 문구로 보여 줘. 수정할 곳이 없으면 유지할 이유를 알려 줘.
AI 답변에서 근거로 삼을 만한 내용이 본문에 빠져 있다면 확인할 사항을 코드 밖에 적어 줘.
```
